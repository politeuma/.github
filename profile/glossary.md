# Glossary / 用語集

| Term / 用語 | English | 日本語 |
|---|---|---|
| Obligation（義務） | One engineering rule (must, must not, may) that one or more legal sources support. | 1つ以上の法源が支える、1つの技術的ルール（すべき・してはならない・してよい）。 |
| Grounding（根拠） | One legal source behind an obligation: jurisdiction, instrument, pinpoint citation, status, review date. | 義務を支える1つの法源。法域・法令名・条項・効力の状態・確認期限を持つ。 |
| Functional equivalence（機能的等価性） | Laws that differ in form but demand the same behaviour from software are grouped as one obligation. | 形は違っても、ソフトウェアに同じ振る舞いを求める法を1つの義務にまとめる考え方。 |
| Section（節） | A short guidance page for people and agents, inserted into AGENTS.md. | 人とエージェント向けの短い指針ページ。AGENTS.md に挿入される。 |
| Condition / when（条件） | A fact about a project, such as handling personal data or shipping to the EU, that decides which sections apply. | どの節を適用するかを決める、プロジェクトの性質（個人データを扱う、EU で提供する等）。 |
| Trigger（トリガー） | A pattern in code or a diff suggesting that a rule may be relevant. | ルールが関係しそうなことを示す、コードや差分中のパターン。 |
| Enforcement level（強制レベル） | L0: read it. L1: detected and reminded. L2: CI blocks the change. | L0：読むだけ。L1：検出して知らせる。L2：CI が変更を止める。 |
| review_by（確認期限） | The date by which a source must be re-checked against current law. | 出典を現行法と照らして再確認すべき期限。 |
| Drift（ドリフト） | A change in the law, a source, or a tool that makes a rule inaccurate. | 法令・出典・道具の変化で、ルールが正しくなくなること。 |
